# PR9 — File des paiements carte échoués, journal des échanges SumUp, Z net par vendeuse

**Demande (15/09/2026, sélection n° 34, 152 et 168) :** mettre en file les
paiements carte échoués de façon récupérable et permettre de les relancer
(n° 34) ; journaliser chaque échange HTTP avec SumUp pour le débogage carte
(n° 152). S'y ajoute le point remonté par le testeur de PR8 : la ventilation
par vendeuse du rapport Z est brute, il faut le net (K0).

Ce qui existe déjà et qu'on **garde** : `payment_attempts` (un essai par
`checkout_id`, statuts pending/paid/failed/cancelled, `attempt_count`),
`POST /api/pos/payments/cb/{checkout_id}/retry`, `GET /api/admin/payments/cb/attempts`,
le rejeu transport transitoire dans `SumUpService._request_with_retry`, la
rédaction `redact_sumup_error`. PR9 ne remplace rien de cela, elle ajoute
une couche au-dessus.

## 2. Hors périmètre
Réessai automatique en tâche de fond (le réessai est un geste de la vendeuse, devant la cliente), remboursement depuis la file, export du journal, alertes e-mail sur échec CB.
